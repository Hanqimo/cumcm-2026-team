# 2026 B 题写作骨架与实验清单

这是一份随建模更新的工作表，不规定固定章节顺序、篇幅或算法。以下段落示例均为本次自拟，不是历史论文原句；任何占位数字都必须由我们的计算或演练记录填入。

## 1. 写作之前先对齐四问的交付

| 小问 | 必须回答 | 建议的正文证据 | 支撑文件 |
|---|---|---|---|
| 第一问 | 定位多边形直径算法；以该直径为直径的圆能否覆盖 | 半平面模型、顶点直径证明、属于测向模型的反例、异常处理 | 几何程序、反例输入与独立核验 |
| 第二问 | 第二检测点选择策略与候选区域 | 定位质量指标、可接收约束、候选域构造、几何与代价对比 | 候选区域数据、计算参数、验证案例 |
| 第三问 | 全向多源自动搜索定位清除；确保全清前提下尽量快；演练指标；三次正式结果 | 信息状态、逐频道覆盖、清除判据、策略伪代码、完整实验结果 | 演练记录、程序版本、三次正式日志 |
| 第四问 | 全向／定向混合时的新策略与算法；演练验证；三次正式结果 | 方向与距离联合观测、新无信号逻辑、定向覆盖与困难案例 | 同上，分别归档第四问 |

正文每一问都有明确答案，不用“详见代码”替代必要的模型和结果。大量中间数据可以放支撑材料，但正文必须给定位入口与关键结果。

## 2. 一套适合今年的章节职责

1. **摘要**：问题结构、关键模型选择、四问结果、验证与实践意义。
2. **问题分析与统一约定**：各问依赖、已知／未知、坐标与角度、时间账、关键假设。
3. **有界测向误差下的定位区域与清除判据**：先回答第一问，再解释其服务后问的方式。
4. **第二检测点的候选域与选择策略**：解释指标、接收条件和行动费用。
5. **全向多源的在线搜索定位清除**：状态、覆盖、调度、反馈更新和结束条件。
6. **定向可见性下的策略扩展**：明确替换哪些第三问规则，新增哪些证明与验证。
7. **实验、可靠性与代价分析**：几何核验、基线、消融、困难案例、正式结果。
8. **适用边界与改进方向**：保证条件、近似误差、计算瓶颈与实际限制。
9. **参考文献与支撑材料索引**：来源与程序、结果、日志的对应关系。

如果把实验紧跟各问写，也可以；最后只汇总跨问比较。不要在每问重复大段背景、相同符号和算法通用介绍。

## 3. 核心模块的论述骨架

### 3.1 第一问：定义与证明分开

可用的段落组织：

> 示向度的误差界限定了以检测点为顶点的正向角域。为避免斜率在竖直方向的奇异性，我们用方向向量的叉积将每个角域表示为两个半平面，其交集即角度观测所限定的区域。以下先在非空有界情形推导直径计算式，再处理空集与无界等情况。

随后写顶点最大距离公式及凸组合证明。最后才写算法、复杂度与数值例子。反例应先证明其角域交集确为所画多边形，再计算直径和包围圆半径。

### 3.2 第二问：先把“较好”具体化

段落应含：第一次观测留下何种不确定性；为什么重复原地检测无效；哪些第二点可能接不到信号；评价的是直径、包围半径还是平均误差；计算依据是否需要概率分布；最终候选区域怎样给出。

不宜只写“采用粒子群求最优点”。若用网格，交代步长与区域边界；若用随机搜索，交代搜索域、重复次数与稳定性；若用经验权重，交代量纲与参数依据。

### 3.3 第三问：状态必须能驱动下一动作

把下面表格填实后再画流程图：

| 当前情况／反馈 | 合法的信息更新 | 下一动作如何决定 | 证据性质 |
|---|---|---|---|
| `direction` | 叠加角域，保留此前同频道信息及必要距离约束 | 重新评估可清除性与下一观测点 | 几何约束 |
| `near` | 距离不超过 5 m 且当时可见 | 可在当前位置清除该频道 | 题设保证 |
| 全向 `no_signal` | 排除该点最小接收半径内的该频道源存在性 | 补足该频道尚未排除区域 | 覆盖逻辑 |
| 定向／类型未知 `no_signal` | 更新距离／方向／类型的联合可能性 | 选择补充方向的停点 | 不可沿用全向圆排除 |
| `cleared` | 标记该频道已清除，成功数加一 | 重排其余任务 | 执行反馈 |
| `no_target_in_range` | 对已知存在且未清除源，可排除清除点 20 m 范围；保持其余可能性 | 判断是否继续观测或另选尝试位置 | 失败也包含信息 |
| 覆盖证书完成 | 确认相关未发现频道不存在剩余源 | 检查其他频道和清除任务 | 结束依据的一部分 |
| 超时／技术异常 | 保存已完成事实和退出原因 | 按实际结果报告 | 不是任务完成证书 |

核心伪代码应给出下述职责，不能用未定义的函数掩盖算法：

```text
初始化当前位置、测向频道和各频道信息状态
循环：
    检查完成证书与运行预算
    根据当前信息生成候选测量和清除动作
    用正文定义的指标与优先级选择一个动作
    串行执行，并等待完整反馈
    按反馈更新相应频道集合和状态
    记录动作、位置、频道、费用、更新前后指标和选择理由
    对空集、无进展或技术异常进入正文说明的处理分支
导出结果，并由日志独立复算费用与统计
```

论文还需定义“生成候选”“选择动作”“完成证书”“无进展处理”的具体内容，否则这只是架构，尚不是可复现算法。

### 3.4 第四问：先写失效点，再写扩展

> 第三问的无信号排除依赖全向辐射。在本问中，检测点即使距源不足最小接收半径，也可能因位于辐射半平面外而接收不到信号。因此，原有圆形排除不再成立。我们保留前问的角度约束和时间模型，改用位置、接收半径与朝向的联合可行集合解释无信号，并补充多方向覆盖条件。

这段交代继承什么、改动什么及理由，之后再接公式和反例。定向模型不能只多一个未知角，却仍沿用所有全向分支。

## 4. 最有价值的图表组合

| 图／表 | 要支撑的判断 | 应标注 |
|---|---|---|
| 单次角域与多次相交图 | 观测如何形成可行区域 | 测点、示向度、误差边界、坐标单位 |
| 直径与包围圆反例图 | 直径不等于两倍最小包围半径 | 顶点、最长距离、两类半径 |
| 第二点候选区域图 | 哪些位置满足定义的筛选条件 | 原测点、首次可行集、接收条件、阈值、色标 |
| 全向覆盖与剩余区域图 | 搜索证书的空间含义 | 已测频道、测点、保证接收圆、圆域边界 |
| 定向失败与修正示意图 | 为什么不能把无信号视为源不存在 | 源到检测点向量、未知／示例朝向、可见半平面 |
| 全流程轨迹与事件图 | 算法实际如何行动 | 有序停点、移动、测向／近距／清除事件；勿只画平滑轨迹 |
| 耗时分解表／图 | 改进来自哪类动作 | 移动、检测、换频、光学定位、清除；总和核对 |
| 基线与消融表 | 哪个改动有贡献 | 同一评价口径、案例数、失败数、时间分布、版本 |

| 正式结果表 | 完成题目交付 | 题面列名、案例编码、真实日志对应项 |

不必机械凑齐十张图表，可以合并；要保留它们承担的证据功能。图后的文字应解释现象与原因，不止写“结果如图所示”。

## 5. 实验设计清单：区分正确性、表现和保证

### A. 几何与规则正确性

- [ ] 359°／1° 跨界、竖直方向与反向误判。
- [ ] 近乎平行、单次测向无界、空集、点／线段等退化情形。
- [ ] 用独立几何检查器核对半平面交点，不只重复调用同一函数。
- [ ] 已知真源与满足误差界的测向序列，逐次检查真源保留。
- [ ] 反例点对直径、最小包围圆半径及测向实现性一致。
- [ ] 计入圆域／距离／负反馈后的区域类型明确，未把所有区域都当凸多边形。
- [ ] 同一坐标重复检测返回固定误差；真实概率结构不明时不强加独立性。
- [ ] 单动作账与总日志账一致；`clear` 不改测向机频道。

### B. 策略对照与消融

建议以现有简单追向策略作为 B0，并逐项加入：B1 几何可行域与清除判据、B2 第二点选择、B3 多目标顺序与停点复用、B4 定向覆盖。为了归因，相邻版本尽量只改变一个模块。

有些模块更改会改变搜索完整性，因此比较应先检查是否完成任务，再比较同等完成条件下的时间。失败版本不能凭“提前退出所以很快”占优。报告成功率／失败数、总时间、中位数、最差值或分位数，明确样本量；正式随机案例少时以描述性结果为主，不夸大统计结论。

自建可复现环境允许同一案例成对比较；官方演练若不允许重放，不能把不同随机案例当作同一案例。保存所有评价案例，不能只挑最好的几次。开发、调参与最终评价分开。

### C. 困难场景与覆盖

- [ ] 源在圆域边缘、接收半径 1000 m、方向朝圆域外。
- [ ] 多个源集中或相距很远；剩余一个源不在此前常去的区域。
- [ ] 目标数分别接近下限与上限，未清完时不会因达到下限退出。
- [ ] 方位角误差取界附近，并检查不同空间误差结构。
- [ ] 定向源位于辐射边界，测试边界包含和数值容差。
- [ ] 每个未发现频道分别具有覆盖记录；走过但未测不计入覆盖。
- [ ] 连续区域覆盖有几何依据；有限网格通过只能称网格验证，除非另有安全裕量证明。
- [ ] 发现覆盖、定位推进、清除完成分别检查，结束理由明确。

### D. 交付一致性

- [ ] 摘要数值、正文表格、结果文件、日志可互相追溯。
- [ ] 每次运行记录策略版本、配置、案例编码、随机种子（若可控）和退出原因。
- [ ] 几何耗时、决策计算耗时、接口等待与虚拟时间口径区分清楚。
- [ ] 第三、四问各三次正式结果和对应导出日志齐全。
- [ ] 零成功时平均时间写“未定义”，未知真总数时不填正式清除比例。
- [ ] 尚未实现、尚未验证、经证明成立与实测支持四种状态不混写。

## 6. 摘要骨架：只在实验完成后填数字

建议按以下逻辑组织，无需固定字数：

> 本文研究有界测向误差与有限接收范围下的无线电干扰源自动定位和清除。针对第一问，将示向度约束表示为半平面交，证明有界定位区域的直径可由最远顶点对获得，并构造可由合法测向产生的反例说明该直径所对应的圆不一定覆盖区域。针对第二问，以【实际采用的定位质量指标】衡量候选检测点，并考虑【实际采用的可接收条件／代价】形成候选区域。针对第三问，结合【覆盖依据】、【定位方法】与【调度规则】构成在线策略；在【真实样本数】个演练案例中，取得【实测完成统计】和【实测时间指标】。针对第四问，利用【实际实现的定向观测与覆盖方法】修正无信号更新，结果为【实测值】。通过【独立核验与困难案例】检验方法，适用范围为【实际能够支持的条件】。

不能把本文手册提出但尚未实现的候选方法填成已完成结果。摘要没有必要列举所有优化器，优先突出题目与方法之间的逻辑。

## 7. 交稿前的五个反问

1. 读者能否从题设一路追到公式、程序、表格和结论？
2. 任何一次行动是否使用了当时并不可知的信息？
3. 任何“保证”是否只有一次成功演练支撑？
4. 任何“最优”是否只是在某个网格、候选集或几个随机运行里最好？
5. 去掉算法名称后，是否仍能说清我们的改动为什么合理、何时有用？

这些问题都能明确回答，才说明文章中的建模与论述相互支撑。
