# 问题三 v4 研究候选运行说明

默认策略 `combined_v4`：继承v3负观测与连续覆盖，加入最近安全清除点、区域接收判据、后续成本选点、目标扫描任务合并。它的参数已经冻结；独立本地审计结果见本模型 verification/report-v1。200秒/点目标尚未达成，本版没有官方模拟器实测结果。

需要 Python 3.10 或更新版本，已测试 numpy 2.2.6、scipy 1.15.3。可以将整个src文件夹复制到新的独立目录运行，勿只复制run_robot.py。程序需要的依赖版本列于requirements.txt。

先做不连接模拟器的自检，配置文件使用自己已有的 `team_no`、`port`。

```powershell
python run_robot.py --check --config "已有配置文件的绝对路径"
```

在模拟器选择问题3演练，待接口就绪后运行并按提示按Enter。

```powershell
python run_robot.py --policy combined_v4 --config "已有配置文件的绝对路径"
```

另可选择 `baseline_v3` 对照旧组合策略、`cost_max` 单独成本改进、`merged_cover` 单独扫描合并。同一演练不能让两个程序同时控制机器狗；需要分别使用可比较案例运行。

本脚本不包含个人队号配置。双击run_practice.cmd时会优先读取本目录config.json，再查找相邻simple-strategy/config.json；明确传入--config最不易弄错。所有请求使用旧版已验证的串行、同请求号重试机制；执行状态不确定时停止后续动作。

每次执行保存 `runs/时间-随机标识/`，包括动作日志、源码快照和散列、参数、结束证书与summary.json。保留官方案例编码、实际干扰源总数、结束截图和导出的.jlog，便于复核总时间及全部清除后的搜索尾部开销。运行日志可能包含自己的队号，分享前按需要处理。

本地预测的9条几何场景只决定候选测点排序；保证接收、保证清除、实际完整覆盖仍单独核验。高成本几何状态或接口等待可能使实机耗时不同于离线审计；旧v3目录和配置完整保留，便于对照。
