# 2026 年比赛工作区

本目录保存本届比赛的题面、数据、模型、代码、运行结果、独立验证和论文。全队按照问题顺序共同推进，同一时间只设置一个活跃小问，不为各小问设置固定负责人，也不使用编辑锁。

## 推进顺序

1. 在 `global/` 中整理题面、全局数据、符号、假设和小问依赖。
2. 从问题一开始，在 `stage/q1` 上汇总全队确认的进展。
3. 针对模型、算法、数据检查、验证和写作建立短研究分支。
4. 当前小问完成后，在 `adopted.md` 中确定正式方案，并将后续需要的结果放入 `exports/`。
5. 将正式结果发布到 `global/accepted-results/`，再合并到 `main`。
6. 从更新后的 `main` 创建下一问的集体集成分支。

## 目录

- `STATUS.md` 是全队当前进度入口。
- `global/` 只保存全题共用内容和经过核验的正式结果。
- `q1/` 至 `q4/` 分别保存各小问的完整研究过程。
- `paper/` 保存论文源文件、采用的图表、笔记和提交版本。

## 当前小问的研究记录

每个小问使用以下文件保持可恢复状态。

- `state.md` 记录当前阶段、模型、算法、验证状态和未决问题。
- `research-log.md` 记录尝试过程和失败方案。
- `decisions.md` 记录集体选择及其依据。
- `comparison.md` 比较候选模型。
- `adopted.md` 指向当前正式采用的模型、算法和运行。
- `exports/` 保存提供给后续小问和论文的正式输出。

实验结果不能直接当作正式结论。只有经过核验并登记在 `adopted.md` 或 `global/accepted-results/` 中的结果，才可以被后续小问和论文引用。
